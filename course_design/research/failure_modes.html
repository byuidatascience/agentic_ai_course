Six failure modes · three dimensions

Each mode is named for the lever that fixes it — the Module 1 steering levers, read backwards. Naming the mode is naming the fix.

01

Tool

The agent's connection to the outside world breaks down.

  • wrong tool
  • right tool, wrong args
  • never called
  • output misread
  • tool errored, agent carried on
LeverTool definitions, descriptions, I/O schemas — usually the text framing the tool, not its code.
02

Grounding

Asserts things not supported by anything it retrieved.

  • fabricated facts / citations
  • nothing retrieved, answered anyway
  • contradicts the right doc
  • accepts a false premise
LeverRetrieval & knowledge state — corpus, what gets retrieved, whether ungrounded answers are allowed.
03

State

Information the agent needs is lost, stale, or poisoned.

  • context exhausted / truncated
  • context degradation
  • memory pollution
  • forgets across turns
LeverState & memory design — what persists, where, and what gets selected into the window.
04

Control

The path is wrong: it doesn't stop, doesn't finish, or wanders.

  • infinite loop
  • budget drain
  • stops too early
  • bad / abandoned plan
  • multi-agent deadlock
LeverDeterministic scaffolding — control flow, routing, step limits, workflow-vs-agent boundaries.
05

Specification

→ Outcome 3

Did exactly what it was told — and that wasn't what was meant.

  • hidden assumption
  • spec drift
  • semantic drift
  • reward hacking
LeverInstructions & spec — system prompt, success criteria, output format, forced re-anchoring.
06

Safety

vs. values · → Outcome 6

Does something harmful or disallowed, even if task-correct.

  • unauthorized action
  • prompt injection
  • leaks secrets / PII
  • alignment faking
LeverGuardrails, permissions, sandboxing, human-in-the-loop.

Dimensions

Modifiers on any mode. Modes give students words; dimensions give them eyes.

Detectability

trains detection
silentloud

A confidently wrong refund is silent — and dangerous. Every eval answers "how would I catch this if it were silent?"

Propagation

trains localization
cascadingisolated

A bad tool result flows three steps downstream. Hunt the trace for the earliest span that went wrong.

Origin

trains attribution
modelcode

Probabilistic failure or deterministic bug — different evidence, different fix. Students reflexively blame the model.

Folded in: coordination → Control code bug → Origin dimension hallucination → split across Grounding & Control tool selection vs. execution → one mode A failure that fits no mode is one students have no lever for.
