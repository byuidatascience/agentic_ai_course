Datasets are test cases for LLMs

Input + what good looks like = a test case. A dataset is a pile of them.

  • Sample what users would reasonably ask, including the ones you know break.
  • Reference outputs don’t have to be exact wording. “Don’t order” is a perfectly good reference.
  • Every failure they found in Lesson X is a free dataset row.

Who grades?

Four kinds of evaluator

Codedeterministic
“Is it true by a rule?”

A function checks the output. Same output → same score, every time.

total <= 10_000 or approved
Free · instant · can't judge meaning
LLM-as-judgeprobabilistic
“Does it meet this criterion?”

A second model reads the output and grades it. For what a rule can't check.

Every claim in the tool results? PASS / FAIL
Cheap · fast · can be wrong too
Human reviewannotation queue
“What does good actually look like?”

Real people (Rosa, Finance) label runs from a queue. The ground truth.

Rosa: FAIL · "missed 40 late shipments"
Slow · costly · the standard
PairwiseA vs. B
“Which of these two is better?”

Two outputs, same input. Pick one. A human or an LLM can do it.

v1 vs v2 → B (more specific)
Relative, not absolute
  • Reveal one at a time. Colors stay the same for the rest of the deck.
  • The first three give each output a score on its own. Pairwise is different: it only says which of two is better.
  • Human review isn’t “instead of” the others. It’s how you know the others are right.

Code: if a rule can check it, use a rule

def within_policy(run, example):
    po = run.outputs.get("purchase_order")
    if po is None:
        return {"key": "within_policy", "score": 1}
    ok = po["total"] <= 10_000 or po["approved_by"] is not None
    return {"key": "within_policy", "score": int(ok)}

Other rules Called search_products? Valid JSON? Mentioned all 23 items? Date math right?

Why first Never changes its mind. Costs nothing. Run it on every example, every time.

  • The $10k policy from request 5 needs no LLM. Students reach for LLM judges by reflex; push back.
  • The run, example signature matches LangSmith custom evaluators; details in the evaluator lesson.

No reference Rubric Right tone for a buyer? Asks when unclear?

Against the reference Correctness / similarity Same meaning as “Don’t order: not low”?

  • These three cards are the mockup’s “judge types” (rubric, similarity, factual/hallucination). They differ by what the judge compares against.
  • String or embedding similarity can also be done in code. An LLM is for “same meaning, different words.”
  • The judge is an LLM: it is non-deterministic and can be wrong. That’s why the next slide exists.

Human review: who grades the grader?

Humans don’t grade everything. They grade enough to trust the judges, and every label becomes a test case.

  • Annotation queue = a to-do list of runs for a person to label, with the rubric beside it.
  • Judge agreement: if the LLM judge and Rosa disagree on 3 of 20, fix the judge prompt before trusting its scores. (2.3.3)
  • The 17/20 is illustrative.

Pairwise: when both pass

CFO · Friday How did shipping go last week?

A · prompt v1 Strong week! About 6,000 orders shipped, ~96% on time. West and Central led.

B · prompt v2 5,982 orders shipped, 95.8% on time. South region data is missing for Thu–Fri; numbers exclude it.

Pairwise judge B. Both are correct. B gives exact figures and flags the missing region, which a board report needs.

  • Lesson X’s “two bosses” again. Scored alone, both would pass “Correct.” Only side by side does one look better.
  • Absolute scores saturate: once everything passes, pairwise still tells v1 from v2. (2.15, 2.2.5)
  • Watch for position bias: LLM judges tend to favor A or B by position. Run it both ways.

One judge, one criterion

The tempting judge

You are grading an inventory assistant.

Rate the response from 1 to 10 for correctness, completeness, grounding, tone, and policy compliance.

Response: “I’ve placed PO-40013 for 300 units at DC-SOUTH. Total: $14,052. Happy to help with anything else!”

7 / 10

7 out of 10 at what?

  • This is what everyone writes first. Ask: “what would you fix?” Nobody can answer from a 7.
  • The output is request 5 from Lesson X: correct-looking, friendly, and a $14k policy violation.

Why one big judge fails

Can’t act on it Which criterion lost the points? A 7 doesn’t point at any lever.

Criteria bleed Friendly tone and a confident answer pull the score up. A $14k policy break gets averaged away.

Can’t calibrate Rosa disagrees with the 7. About grounding? Policy? You can’t fix one part of the prompt.

1–10 is mush What’s the difference between a 6 and a 7? Run it again: 8.

Split it: one evaluator per criterion

Each evaluator answers one question. Each failure points at one lever.

  • The verdict colors on the right are the Lesson X failure-mode colors: criterion → failure mode → lever.
  • Note that “Within policy” moved to code. Splitting criteria apart is often how you discover a rule can check one of them.
  • Bonus: you can now improve one judge without touching the others, and track each criterion’s pass rate separately.

A good judge prompt

Criterion: Grounded

PASS if every fact in the response (items, quantities, stock levels, prices) appears in the tool results below. FAIL if any fact is missing from them, or the response assumes something it never checked.

Example FAIL: says “DC-SOUTH is low” when no stock lookup for DC-SOUTH was made.

Tool results: {tool_results}
Response: {output}

Explain your reasoning, then answer PASS or FAIL.

  • One criterion. If you wrote “and,” make two judges.
  • Pass / fail, not 1–10. Easier to agree on, easier to check.
  • Say what pass and fail mean, with a real example of each.
  • Reasoning first, verdict last.
  • Check it against people. Does it agree with Rosa?
  • The example FAIL is a real failure from the notebook. Your best examples come from your own traces.
  • Students will ask “what about partial credit?” Split the criterion until pass/fail makes sense.
