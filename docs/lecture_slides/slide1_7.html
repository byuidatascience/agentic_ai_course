Where does it run?

  • Start on the left: recap 1.6. Someone else started the server; we only knew its URL.
    1. Today there’s no second machine.
    1. uvx downloads the package and starts it as a child of your agent. No URL, no port.
    1. They talk through the process’s own input and output: stdin and stdout.
    1. Who talks to arxiv.org? The server, not the agent. The processing happens on your machine. (Quiz item d asks this.)
    1. LangChain opens one session per tool call. For stdio, the server starts for the call and exits when it returns. That’s why the tools still work after the async with block.

Two ways to connect

stdio: Friendly Neighborhood Spider-Man

  • Local. On your machine
  • Swoops in when your agent calls, gone after
  • Everyone gets their own (the Spider-Verse)
  • uvx ... · npx ...

HTTP: Stark Industries

  • Remote. Someone else’s machine
  • Always on, before you connect
  • Serves many clients at once
  • https://docs.langchain.com/mcp
  • Spider-Man is new today; Stark is the 1.6 recap. (Moved here from 1.6 per the scope cut.)
  • Ask: which one is Mateo’s arXiv server? Why is that fine for him? (One lab member, one machine.)
  • Don’t define the difference for them yet. The pair quiz makes them say it.

One Agent, Two Servers

One more entry

config = {"mcpServers": {
    "arxiv": {"command": "uvx", "args": ["arxiv-mcp-server"]},

One more entry

ARXIV_FOLDER = "/root/.arxiv-mcp-server/papers"   # where the arXiv server saves papers
LAB_FOLDER = "/content/lab_papers"                # where the lab looks

config = {"mcpServers": {
    "arxiv": {"command": "uvx", "args": ["arxiv-mcp-server"]},
    "files": {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", LAB_FOLDER, ARXIV_FOLDER]},
}}

The folders at the end of args are the only folders it can touch.

  • npx is Node’s uvx. This server is written in TypeScript, and Colab already has Node.
  • Two folders: the lab’s, and the arXiv server’s hidden one, so the agent can move papers across.

d. Which is which?

Config A

config = {"mcpServers": {
    "fetch": {"command": "uvx",
              "args": ["mcp-server-fetch"]},
}}

stdio. Runs on your machine, even though it fetches web pages.

Config B

config = {"mcpServers": {
    "docs": {"url": "https://docs.langchain.com/mcp"},
}}

HTTP. Runs on LangChain’s machine. You only send requests.

  • The trap: “fetch touches the internet, so it must be HTTP.” No. The transport is about how your agent talks to the server, not what the server does.
  • command → your agent starts it → your machine. url → someone else started it → their machine.

Your Project 1 agent · main.py

config = {"mcpServers": {
    "docs":  {"url": "https://docs.langchain.com/mcp"},
    "files": {"command": "npx",
              "args": ["-y", "@modelcontextprotocol/server-filesystem", NOTES_FOLDER]},
    # "???": one you pick
}}

async def build_agent():
    async with MCPAdapter(config) as adapter:
        mcp_tools = await adapter.list_tools()
    return create_agent(MODEL, mcp_tools + my_tools)

Your 1.6 build_agent, with the URL swapped for a config. Locally you need uv and Node.

  • NOTES_FOLDER is an absolute path to a folder they choose. Don’t give it your home directory.
  • stdio servers now run on their laptop. Same code; the machine changed.
  • Every server counts toward the “most MCP servers connected” leaderboard.
